## UIモックで比較・確認する方針

2026-09-30のモックは、日常的にMRを連続レビューする作業画面を起点にする。低彩度のグレーを土台に、選択と主操作だけに控えめな青緑を使う。差分の追加/削除・状態色はそれぞれの意味に限定する。大きいカードの繰り返しより、薄い区切りと揃った行で情報を並べる。

- 通常幅: ナビゲーション、MR一覧、選択したMRの詳細を横並びにする。一覧から次のMRへ移る操作を短くする。
- 狭幅: ナビゲーションを縮小し、一覧と詳細を切り替える。差分を常時三列に押し込まない。
- 詳細: タイトル・状態・操作を上部に揃え、議論/変更/概要の順にタブを並べ、MRを開いた直後は議論を表示する。変更はファイルを選んで読み、関連する議論を同じ文脈で確認する。
- 検索: プロジェクト探索と過去MR検索を独立した入口にする。タイトル/説明とMR状態の条件を明示する。
- レビュー: 本文入力、下書き、返信、解決、承認の操作位置と状態表示を共通化する。

追加方針（2026-09-30）:

- プロジェクト一覧からも、MR詳細のプロジェクト名からも、そのプロジェクト専用の画面を開く。見出しのプロジェクト名の横に「MR」「ブランチ」のタブを置く。ブランチは更新の新しい順に、名前、デフォルト・保護・マージ済み、最新コミット（短いSHA・タイトル・作成者・時刻）を示し、行を選ぶとそのブランチをソースとするMRをプロジェクトのMR一覧に表示する（GitLabで開く操作は行の外）。絞り込んだブランチはMR一覧の条件のタグで示し、外すか「MR」タブを選び直すとプロジェクトのMR一覧の初期状態に戻る。ブランチからMR一覧への移動は履歴に残り、戻る操作でブランチ一覧へ戻れる。名称・namespace・説明を簡潔に示し、現在/過去のMRをプロジェクト内で検索する。MR詳細から戻っても対象プロジェクトと絞り込み条件を維持する。
- 変更タブの上部に、比較対象を選ぶ横向きのタイムラインを置く。先頭は「MR全体」、続いて古い順にコミットを並べる。コミットを選ぶと、その親からの変更だけを表示し、SHAと件名で対象を識別できるようにする。MR全体の行番号で付けた議論を、コミット差分へ誤って重ねない。
- 議論を左端の既定タブとし、コメント本文と返信をすぐ読める領域を確保する。概要は必要なときに説明全文と付帯情報を確認する参照画面とする。CI・承認数・変更ファイル数は短い一列にまとめ、大きな統計カードを追加しない。
- 返信・解決・コメント入力は議論タブにまとめる。返信欄は返信するスレッドの中に開き、下端の新規コメント欄とは本文を分けて保持する。Escまたは「閉じる」で閉じても本文は残る。概要に議論や入力欄を重複表示しない。新規コメント・下書きはMRごとに保持し、概要や変更を見て戻っても本文を失わない。コメント本文と返信本文は同じ可読性を確保する。

モックは`#mock`で開く独立したプレビューとする。架空データを使うことと未接続を常時表示し、投稿・承認はローカルの操作シミュレーションに限定する。画面上の件数はfixtureと一致させる。実GitLab接続、ディスクへのキャッシュ保存、性能改善が実装済みであるとは表示しない。

この段階で確認するのは情報密度、画面の役割、操作順、一覧と詳細の関係、明暗テーマ、キーボードと狭幅での扱いやすさ。配色や密度を調整して基準を決めてから、接続機能の実装へ進む。サンプルの軽快さを実データの性能検証の代わりにはしない。

実装したモックの基準値はナビゲーション152px（手動折りたたみ・1100px以下で48px）、MR一覧314px、差分ファイル欄160px。狭幅では一覧/詳細を切り替え、ファイル選択を上部へ移す。本文・コード13px、補助情報11pxをテーマで定義し、見出し以外の過度な太字を避ける。追加/削除の背景色と文字色は明暗それぞれの専用トークンを使う。操作中の内容はメモリ上だけで保持し、リロードでリセットする。

内容を繰り返す上部の「Review workspace / …」バーは設けず、作業内容をウィンドウ上端から表示する。UIカタログなどの補助機能は下部へまとめる。未接続・サンプルデータの表示は24px高の下部ステータスバーに集約し、ナビゲーションを折りたたんでも常に確認できるようにする。本文・コメントの文字は小さくせず、画面枠の余白と重複情報を減らす。

### 実装済みクライアントの画面構成（2026-10-09、2026-10-13改訂）

実装済みクライアントを、モックで決めた「一覧を見ながら次々にレビューする」構成へ作り直した。配色・部品・操作の置き方もこの構成に合わせて改めた。2026-10-13に、開いたMRをサイドバーのタブで行き来できるようになったため、一覧と詳細を横に並べる3ペインをやめ、一覧かMR詳細のどちらかを全幅で表示する構成に改めた。

**レイアウト。** ナビゲーション（208px、折りたたみ時52px）の右に、一覧かMR詳細のどちらかを全幅で表示する。開いたMRはURLの`mr=<projectId>-<iid>`で表し、一覧はMR詳細の下で表示しないまま保持するので、一覧の条件・入力・スクロール位置はMRを開いても保たれる。詳細の戻るボタン（Esc）で開いた元の一覧へ戻る。ボタンの名前は「レビュー依頼に戻る」のように戻り先を示す。一覧から開いたMRでは、戻る操作はその一覧までの履歴を戻る（MR内のタブ切り替えやサイドバーでのMR切り替えも含めて戻る）。そのためブラウザの戻るで同じMRを開き直さない。URLや別の画面から直接開いたMRでは、一覧を新しい履歴として開く。別のMRへはサイドバーのタブで移る。接続設定は一覧を持たない全幅のページとする。読み込み中・更新中・保存済みの表示は、出たり消えたりする行として差し込まず、最初から確保した場所の中身を入れ替える（一覧は高さ固定の状態行、MR詳細はヘッダー上段の「保存済み · 時刻」、起動時の接続確認とMRの読み込みは完成後と同じ枠の中に表示する）。旧形式の`#client/mr?...`はレビュー待ち一覧から開いた形へ読み替える。

**幅の使い方。** 主な利用環境は27インチ4K・拡大率200%の最大化（実効1920×1080）で、広い幅の空白をなくすことを優先する。MRを開いてもナビゲーションの展開・折りたたみは変えない（MRは既に全幅を使うため）。ペインの左右余白は16pxに揃える。議論タブは幅の上限を設けず、詳細ペインの幅（左右余白を含む）が1200px以上のときはスレッドの右に340pxの列を置き、未解決スレッドの一覧（選ぶとそのスレッドへ移動）と未公開レビューを上端に固定して表示する。1200px未満ではスレッド、未公開レビュー、新規コメントの順の1列とし、未解決の絞り込みは一覧上部の切り替えを使う。行・ファイル位置を持つスレッドは、開いている間だけ対象のコードを示す。スレッドの幅が960px以上ならコメントを左（どのスレッドでも目線の始まりを揃える）、コードを右に並べ、コードは長いスレッドを読む間も上端に固定する。狭いときはコードをコメントの上に置く。コードは対象行の前4行・後2行を同じハンクの中から取り、対象行を左端の線で示す。MRの現在のheadへのコメントは変更タブと同じ差分ページ（最大10ページ）から差分として表示し、古いheadへのコメントや差分ページにないファイルは、コメント時点のコミットのファイル本文から表示して「コメント時点のコード」と明記する。ファイル全体へのコメントにはコードを出さない。コメントの文章は読みやすさのため最大760pxで折り返し、コードブロックと表はスレッドの幅いっぱいまで使う。差分の検索欄は説明文を出さない1行の欄とし、説明はツールチップに置く。

**配色。** 青みを抑えたニュートラルなグレーを土台にし、青は主操作・リンク・選択の目印（左端の線やアイコン）に限る。選択行の背景は青ではなく明るいグレーにする。面は「ナビゲーション < 一覧 < 詳細 < カード」の順に、ダークでも目で分かる段差で明るさを変える。主ボタンの塗りは白文字が読める濃さの青（`primaryFill`）とし、文字・アイコン用の明るい青と分ける。状態表示は塗りつぶさず枠で示し、MergedはGitLabと同じ紫、情報色（CI実行中など）は青と区別できる水色にする。頭文字アバターは状態色を使わない淡い色にする。ダークの差分は文字色を変えず背景だけを色付けする。値はすべて`src/theme.ts`のトークンにあり、`palette.surface`で各ペインの面と選択色を参照する。

**操作の出し方。** 常時見せるボタンは各画面の主操作だけにする（MR詳細では「承認する」）。更新・GitLabで開く・固定などはツールチップ付きのアイコンボタンにし、一覧行のCI確認・プレビュー・固定は行にマウスを乗せたときかフォーカス時に表示し、固定済みの行ではピンを常に表示する（固定の表示と解除を同じ部品にする）。キーボードでは、一覧で`J`/`K`が行のフォーカスを移し（Enterで開く）、MRを開いている間は開いた元の一覧の前後のMRを開く。`/`で一覧の検索欄、`Ctrl+K`で検索タブ、`Ctrl+O`でURLから開く。一覧内では矢印キーと`J`/`K`でフォーカスを移す。

**共通部品。** 一覧ペインは`PaneHeader`（タイトルまたは並列の一覧を切り替えるタブ・アイコン操作・検索）、`PaneStatus`（件数・鮮度の一行）、`ListRow`（行全体で開き、操作は行の外に置く）で組む。空・未選択は`PaneEmpty`、MR状態は一覧の行とサイドバーのタブでは`MergeRequestStateIcon`、ヘッダーとプレビューではアイコン付きの`StatusPill`、時刻は`RelativeTime`、CIは`PipelineStatus`、ページ移動は`Pager`、設定の各ブロックは`SettingsSection`を使う。

**詳細ペイン。** 縦のスクロールは詳細ペイン1つにまとめ、差分・ファイル本文・入力欄の中では縦にスクロールさせない（差分はファイル見出し、入力欄は書式ツールバーをMRヘッダーの下に固定する）。独自にスクロールするのは、上端に固定した変更ファイル一覧と議論タブの右列だけとする。ヘッダーはスクロールしても上端に残し、プロジェクト・MR番号・操作、タイトル、状態と付帯情報、タブ（未解決数付きの議論・変更・概要）の順に並べる。承認状態は詳細を開いた時点で取得し、ヘッダーで承認・取消できる。ヘッダーの主操作は承認だけとし、マージ・自動マージ・リベース・変更の要求・タイトル・Draft・ラベル・マイルストーン・クローズ/再オープンは横の「その他の操作」メニューにまとめる。マージ可否（GitLabの判定を日本語にしたもの）は付帯情報の行に示し、マージ・クローズ・リベース等は確認ダイアログを経て送る。担当者・レビュアーはヘッダーに常に表示し、横の編集ボタンからダイアログで変更する。アプリのバージョンは下端のステータスバー右側に表示する。投稿結果の確認や位置エラーの警告はタブ内容の上に出し、長い議論の末尾に埋もれさせない。概要タブは説明と、作成者・ブランチ・担当・レビュアー（各人の横に再レビュー依頼）・承認・ラベル・マイルストーンの一覧を並べる。ラベルは`LabelChip`で表示し、GitLabのラベル色は小さな色見本にだけ使って文字色はテーマに従う。

**議論。** 各コメントは発言者のアバター、名前・時刻の一行、14pxの本文の順に並べ、未読は左端の線で示す。スレッドの解決状態は上部の1つのボタンで表示と切り替えを兼ねる（「未解決」を押すと解決済み、「解決済み」を押すと未解決に戻す）。スレッド（行コメント・解決可能・返信あり）は上部のボタンで折り畳め、解決済みは折り畳んだ状態で始まる。返信のない単独コメントは折り畳まない。アバターはGitLabの`avatar_url`を使うが、Webviewは画像URLを直接読み込まない。GitLab Webと同じ画像を出すため、Rustが接続先インスタンスの`uploads/`配下の画像を認証付きで、画像を設定していない利用者にGitLabが返すGravatar（`https://`の`gravatar.com`の`/avatar/`）を認証情報なしで取得し（PNG/JPEG/GIF/WebP、256KBまで。Gravatarの取得はGitLab APIと別の同時実行枠を使い、外部へ出られない環境でもGitLabの取得や書き込みを待たせない）、`data:` URLとして返す。それ以外の外部ホストや取得失敗は頭文字で表示し、CSPの`img-src`は変えない。

**議論の読み込みと表示位置。** 議論は古い順に並べたまま、新しいものから読み込む。GitLabの議論APIは並び順を指定できないため、1ページ目の`X-Total-Pages`（RustがSnapshotの`totalPages`として返す）で最後のページを知り、最後のページを先に取得する。最後のページが10スレッド未満なら1つ前のページも合わせて読み込む。総ページ数が返らない場合は従来どおり先頭から順に辿る。取得したページは最大10ページで、上端の「以前の議論を読み込む」または上へのスクロールで1ページずつ古い方へ広げる。自動更新は最新のページだけで行い、古いページは返信・解決などそのスレッドへの操作の後に更新する。

議論タブを開いたときは、既読のコメントがあり未読もある場合は最初の未読コメントを、初めて開いたときや未読がないときは最新コメントのスレッドの末尾を表示する。位置はスレッドと下書きの取得が揃ってから描画前に一度だけ設定し、途中の位置を見せない。上に古い議論を追加したときや更新で上側のスレッドが伸びたときは、画面上端のスレッドの位置を保つ。古いページの自動読み込みは利用者がスクロール操作をしたときだけ行う。別のタブから戻ったときは同じ表示中の位置に戻し、MRを開き直したときは改めて最新から表示する。

**差分。** 表示形式はファイル見出しのボタンで「統合表示」と「左右に並べて比較」を切り替え、選択はこの端末に保存する。左右表示では左に変更前、右に変更後を置き、削除行の並びと続く追加行の並びを1行ずつ対応させ、変更のない行は左右両方に出す。長い行は横スクロールではなく折り返し、左右の行の高さを揃える。コメントは左側からは変更前の行、右側からは変更後の行に付け、変更のない行は右側の1つのボタンで新旧両方の行番号を持つ位置に付ける。統合表示の行は最小22pxで、コメントの「+」ボタンは行番号の右に重ねる。複数行は「+」からのShift+クリック、行番号上のドラッグ、「+」でのShift+↑／↓で同じハンク内に限って選び、選んだ行は行番号側の左端の線（統合表示では行番号の背景も）で示して、入力欄は終端行の下に開く。範囲コメントは終端行の下に置き、スレッドの下端に「12〜15行目へのコメント」と示す。「空白を無視」はファイル見出しの切り替えで、端末に保存する。長い行は統合表示でも折り返す。ハンク間には省略行数を示す。ファイル一覧は詳細ペインの幅が820px以上のときだけ横に出し、狭いときはヘッダーの前後ボタンと「n/全体数」で移動する。行は1ページ最大600行のため、行ごとのスタイル付き部品を使わず、コンテナ側の1組のスタイルで描画する。

明暗テーマは初回にOSの設定に従い、手動で切り替えた選択はこの端末に保存する。

### コミットタイムラインの配置

タイムラインは「変更」タブの直下、ファイル一覧とコード差分の上に置く。コードの横幅を減らさず、ファイルを切り替えても比較対象が見える構成にする。先頭の「MR全体」は集約表示であり、その後のコミットは古い順。コミットの差分は常に親からの変更とする。

各項目は短いSHAと件名を持ち、長い件名は省略してツールチップで全文を確認する。項目が多くても帯を複数行にせず、横スクロールと送りボタンで移動する。左右矢印で選択を移動し、HomeでMR全体、Endで末尾コミットへ移る。選択中の項目は色と選択表示で識別でき、比較元と比較先もタイムライン直下に示す。比較元と比較先の表示の横に「比較元バージョン」の選択を置き、過去のバージョンを選ぶとそのバージョンから最新までの差分を閲覧専用で表示する（リベースの注記を出す）。

### ファイル全体の表示

ファイル見出しの近くに「差分 / ファイル全体」を置く。「ファイル全体」は抜粋差分をつなぎ合わせず、選択した版の変更後の内容を先頭から末尾まで表示する。MR全体を選んだ場合はMRの最新状態、コミットを選んだ場合はそのコミット時点の内容とし、SHAを表示して区別する。

表示モードは同じMR内のファイル・コミット切り替えで維持する。全文は一列の行番号と通常のコード表示を使い、差分の削除行や追加記号を混ぜない。既存の行コメントマーカーは差分側で表示する。新規コメントは差分・全文どちらからも、ファイルと旧/新側・行・SHAを指定して入力できる。全文未取得と空ファイルは異なる状態として示し、未取得の際に抜粋を全文と表示しない。将来の実接続でもファイル取得とキャッシュをコミットSHAに紐づけ、表示中の版と最新ブランチの内容を混在させない。

## 体験の優先順位

1. 現在の接続先、プロジェクト、検索対象がすぐ分かる。
2. 一覧を見ながら比較でき、詳細から戻っても文脈が残る。
3. データがない、未取得、更新中、古い、取得に失敗した、を区別できる。
4. マウスでもキーボードでも日常操作を繰り返せる。
5. MR・差分・議論が多くても、入力・切替・スクロールを止めない。キャッシュ表示後も更新状況が分かる。

画面ごとに新しい装飾を考えるのではなく、検索・一覧・詳細・設定という4種類の構造を再利用する。大きなヒーローや統計カードを既定のトップ画面にしない。

| 動き | 必要な状態変化だけ、100〜160ms程度。reduced-motionに従う |
| アイコン | 1つの意味に1つのアイコン、1つのアイコンに1つの意味。行内の状態アイコンは16px。対応表は下記 |

アイコンの対応: プロジェクト`Source`、ディレクトリ`Folder`、ブランチ`AltRoute`、MR一覧`RateReview`、To-Do`Inbox`、設定`Settings`、URLから開く・リンク`Link`、GitLabに接続`Login`、トークンの更新`Key`、再取得`Refresh`、外部で開く`Launch`、固定（MRのみ）`PushPin`、お気に入り（プロジェクトのみ）`Star`、承認済み（状態）`ThumbUpOutlined`（自分の承認は塗りの`ThumbUp`）、Draft`EditNote`、未読`MarkChatUnread`、デフォルトブランチ`Home`、保護`Lock`、マージ済み`CallMerge`、アーカイブ済み`Inventory2`、未公開レビュー`ScheduleSend`、To-Doの種類（担当`AssignmentInd`、メンション`AlternateEmail`、承認依頼`HowToReg`、レビュー依頼`PersonSearch`、マーク`BookmarkBorder`、CI失敗`ErrorOutline`、マージ不可`Block`）、承認する（操作）`Check`、成功`CheckCircleOutline`、エラー`ErrorOutline`、警告`WarningAmber`、待機`Schedule`、中止・クローズ・ジョブの取消`DoNotDisturbAlt`、ジョブ・パイプラインの再実行`Replay`、手動ジョブの実行`PlayArrow`、ファイルツリーの表示切り替え`ViewSidebar`、ツリー表示`AccountTree`、前後のファイル`KeyboardArrowLeft/Right`、前後の未解決スレッド`KeyboardArrowUp/Down`。スレッドの解決状態は`ResolveToggle`（未解決`RadioButtonUnchecked`／解決済み`CheckCircle`）で表示と切り替えを兼ねる。

**状態は文字より形と色で示す。** 認知負荷を下げるため、一覧の行に並ぶ状態（MR状態・Draft・CI・承認・未読・ブランチやプロジェクトの属性）は文字のチップにせず、`StateIcon`（16pxのアイコン、必要なら数だけを添える）で示す。状態名はツールチップと支援技術向けの名前に残し、色だけに頼らず形でも区別する（自分の承認は塗りのアイコン、CI実行中は回転、動きを減らす設定では止める）。To-Doの種類、差分上の未公開レビュー、MRヘッダーのマージ可否もアイコンだけにし、種類や理由はツールチップで示す。MR状態とDraftはヘッダー・プレビューではアイコンに短い文字を添える。

これらは実データの一覧で確かめて固定する値。アクセント色は暫定で、色だけで状態を伝えない。未接続はニュートラル、通信失敗はerror、更新中はprogressとして区別する。ライト/ダークは同じレイアウトと情報階層を使う。

## 検索画面

上から「検索対象と入力」「フィルター」「検索結果と取得範囲」。プロジェクト検索とMR検索はタブで分け、どちらを検索しているか曖昧にしない。全状態/未マージ等の初期条件を隠さない。

結果行はタイトルだけでなくnamespace/project、MR番号、状態、作者、更新時刻を示す。同名プロジェクトや別プロジェクトの同じMR番号を見分けられるようにする。本文の全文を一覧で取得・表示しない。空結果には適用条件と解除方法を示す。

「全30件」と「30件取得」は区別する。サーバー検索、以前の検索結果、保存済みデータ内の検索は明示的に切り替える。検索結果の順序は使用したAPIのsort条件に従い、関係のないローカル履歴を混ぜて一つのランキングにしない。

## レビュー画面と大量データ

MR詳細は議論・変更・概要のタブを共通にし、ファイル選択、位置、展開状態を戻る操作で復元する。タイトル/説明の検索とコメント表示を混同しない。変更タブは選択ファイルを中心に表示し、解決済み議論は折り畳む。追加読み込みと省略状態を隠さない。

通常のレビュー操作は、全体/行コメント、返信、自分のコメント編集・削除、解決/再開、下書き公開、承認/取消。本文入力・保存・送信状態はReviewComposerに統一する。承認状態はコメント送信状態と分ける。「確認済みファイル」はローカル進捗と明記し、差分版が変わったら再確認を促す。

下書き一覧にはローカル保存とサーバー保存を区別して示す。公開する本文と件数を確認でき、Webで作成した下書きを暗黙に公開しない。複数公開の一部成功は項目ごとに表示する。投稿結果不明は失敗と区別し、確認前に再送へ誘導しない。

キャッシュがあれば即座に内容を出し、更新中に全画面をSkeletonへ戻さない。投稿・解決で変わるスレッドだけを更新し、一覧位置や入力本文を維持する。権限失効時はキャッシュ表示を続けて迂回しない。

長い一覧・差分・議論は仮想化する。可変高の本文でもスクロール位置が飛ばないこと、キーボードで未描画項目へ移動できること、編集中の下書きが消えないことを確認する。詳細な性能目標と負荷規模は[全体設計](architecture.md)第14節に従う。

コメントの種類、未公開レビュー、編集・削除と実接続で必要な機能の境界は[コメント・レビュー対応方針](comment-review-parity.md)に従う。入力中の下書きとレビューへ追加済みの未公開コメントを区別し、公開ダイアログには追加済みの内容だけを含める。Markdownの入力は書式をその場で表示するリッチ入力を既定とし、記法を直接編集するMarkdown表示へ切り替えられる。リッチ入力が本文の描画結果を変えてしまう場合（HTMLなど）はMarkdown表示で開き、利用者の操作なしに本文を書き換えない。リッチ入力の文字組みは本文表示と共通のスタイルを使う。

## キーボード・フォーカス

- Ctrl+K: 移動/検索入口。Esc: パネルを閉じる、元の操作要素へフォーカスを戻す。
- Enter: 検索語を適用、選択した項目を開く。検索語以外の条件（状態・人・ラベル・ブランチ・更新日・プロジェクト・グループ）は「＋条件を追加」またはタグから編集し、選んだ時点で適用する。適用中の条件は検索語も含めてすべて外せるタグで示し、並び順は条件ではないためタグにせずプルダウンで選ぶ。テキスト入力中にグローバルショートカット（Ctrl+K・Ctrl+Oを含む）を横取りしない。
- ?: ショートカット一覧。MR内ではN/Pで未解決スレッド、]/[でファイルを移動する。
- Tab: 可視の操作要素を論理順に移動。フォーカスを色だけでなく輪郭でも示す。
- 詳細を開いたら見出しへ、戻ったら元の行へフォーカスを復元する。
- 表の矢印キー操作は一覧部品のパターンとして実装する。単なる行全体クリックに依存しない。
- 非同期更新はaria-liveで控えめに通知し、定期更新で大量の読み上げを発生させない。

一覧を再取得するたびにスクロール位置や選択を初期化しない。行が対象から外れた場合はその理由を示し、別の行へ黙って選択を移さない。

## AI実装で守る変更手順

1. 新機能の前に、既存の画面パターンと共通部品で表現できるか確認する。
2. 機能の状態表を作る。正常時だけの画面を完成としない。
3. 新しい共通部品・variantを作ったらUIカタログに状態例を追加する。
4. テーマ・型・lint・代表動作テストを通す。
5. 明暗、狭幅/通常幅、長い日本語・長いパス、キーボード操作を確認する。
6. 共通部品の見た目を変えた場合は `npm run ui:snap` で代表画面のスクリーンショット差分を確認し、意図した差分だけを `npm run ui:snap:update` で基準へ反映する。UIカタログの `catalog-*` id を持つ節は自動で撮影対象になる。

静的チェックは、現在の色直書き・直接HTTP検出に加え、直接invokeをIPC層以外で使わない規則を追加する。画面単位のMUIテーマ作成を禁止する。色や寸法の全てを正規表現だけで保証するとは考えず、共通部品とレビューを併用する。

スクリーンショット基準はプロジェクト一覧、過去MR検索、MR概要、diff、議論、接続エラーの代表状態に絞る。OS・フォント・WebView2バージョンを記録し、レンダラー更新による差と意図しないレイアウト差を区別する。データfixtureは匿名化した固定データを使う。
