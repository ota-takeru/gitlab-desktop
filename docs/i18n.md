# Localization

The interface is translated with ICU MessageFormat (`intl-messageformat`). English is the source language and the fallback for any message a language does not have yet.

## Files

- `src/i18n/messages/<locale>/<feature>.json` holds one feature's messages. The key `settings.title` is `title` in `settings.json`.
- `src/i18n/messages/en/index.ts` lists the English files; their keys are the type `MessageKey`, so an unknown key fails type checking. A new feature file is added there and to every language folder.
- Languages other than English load only when chosen. `src/i18n/locales.ts` lists the supported languages and their names, written in the language itself.

## Writing messages

- Use `const t = useT()` in components and `translate()` outside React. Both take a key and optional values: `t('time.minutesAgo', { count })`.
- Keys name the meaning and place, not the wording: `review.thread.resolve`, not `review.resolveThisThread`.
- Write whole sentences with placeholders. Do not join translated fragments, since word order differs between languages.
- Counts use `{count, plural, one {# comment} other {# comments}}` in English even when the Japanese text needs no plural.
- Dates, times and numbers go through `Intl` with `currentLocale()`, never a fixed `'ja-JP'`.
- Not translated: data from GitLab (titles, descriptions, labels, branch names), GitLab's own state names when shown as GitLab shows them, and code.

## Tests

- Tests run in Japanese (`src/test/setup.ts`) and find elements by their Japanese text.
- `src/i18n/i18n.test.ts` checks that every file parses, uses the same placeholders as English, and that Japanese has every message.
