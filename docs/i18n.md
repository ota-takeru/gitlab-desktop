# Localization

The interface is translated with ICU MessageFormat (`intl-messageformat`). English is the source language; every language must have every message, which the tests check.

## Files

- `src/i18n/messages/<locale>/<feature>.json` holds one feature's messages. The key `settings.title` is `title` in `settings.json`.
- `src/i18n/messages/en/index.ts` lists the English files; their keys are the type `MessageKey`, so an unknown key fails type checking. A new feature file is added there and to every language folder.
- Every language, English too, loads only when chosen, so no language's text is in the start-up bundle. `src/i18n/locales.ts` lists the supported languages and their names, written in the language itself.

## Languages

English, Japanese, Simplified and Traditional Chinese, Korean, German, French, Spanish, Brazilian Portuguese and Russian. The OS language picks the closest one: the same script for Chinese (zh-TW → zh-Hant), else any variant of the language (pt-PT → pt-BR), else English.

Japanese is the app's original text. The other languages were machine translated from English with GitLab's own terminology where known, and have not been reviewed by native speakers yet. Corrections go straight into the language's files.

Adding a language: copy the English folder, translate it, add the tag to `supportedLocales` and `localeNames` in `src/i18n/locales.ts` and its MUI locale in `src/App.tsx`. The tests require every key in every language. Vitest caches the test file with the folder list expanded, so run `npx vitest --clearCache` once after adding a folder.

## Writing messages

- Use `const t = useT()` in components and `translate()` outside React. Both take a key and optional values: `t('time.minutesAgo', { count })`.
- Keys name the meaning and place, not the wording: `review.thread.resolve`, not `review.resolveThisThread`.
- Write whole sentences with placeholders. Do not join translated fragments, since word order differs between languages.
- Counts use `{count, plural, one {# comment} other {# comments}}` in English even when the Japanese text needs no plural.
- Dates, times and numbers go through `Intl` with `currentLocale()`, never a fixed `'ja-JP'`.
- Not translated: data from GitLab (titles, descriptions, labels, branch names), GitLab's own state names when shown as GitLab shows them, and code.

## Native errors

- Rust keeps its Japanese `message` as the fallback and log text, and names the frontend message with `.key("native.…")`, adding placeholder values with `.value(name, value)`.
- `normalizeGitLabError` shows the translated message when the key is known and the Rust text otherwise. Translations stay in the frontend files; Rust has none.
- Text Rust shows itself, such as a folder picker title, is passed in already translated by the frontend.

## Tests

- Tests run in Japanese (`src/test/setup.ts`) and find elements by their Japanese text.
- `src/i18n/i18n.test.ts` checks that every file parses, uses the same placeholders as English, and that every language has every message. `src/i18n/native.test.ts` checks that every `native.*` key used in Rust exists and every one in the file is used.
- `npm run design:guard` fails on Japanese left in strings or JSX of shipped code; development screens, fixtures and `src/i18n` are exempt.
